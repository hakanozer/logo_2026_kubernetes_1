Atölye öncesi kontrol

02 · Ortam kurulumu

Birincil çalışma alanı Rancher Desktop’ın tek node’lu k3s kümesidir. Kurulum ekranlarının adları sürüme göre küçük fark gösterebilir; ayarların amacı aynıdır.

Makine gereksinimi ve seçim

  • En az 8 GB RAM’i VM/Kubernetes’e ayırın; ana işletim sistemi için ek bellek bırakın. 4 CPU çekirdeği önerilir. Diskte image katmanları ve Elasticsearch için en az 20 GB boş alan bulundurun.
  • macOS: Apple Silicon (arm64) ve Intel (amd64) host mimarisiyle uyumlu Rancher Desktop paketi indirin.
  • Windows: WSL2 etkin ve güncel olmalı; Rancher Desktop’ın WSL dağıtımına erişmesine izin verin. Kurumsal cihazlarda sanallaştırma/policy yetkisini önceden kontrol edin.
  • Bu eğitim için genellikle containerd önerilir. `nerdctl` ile `k8s.io` namespace’ine image yükleyeceğiz. Docker Engine (Moby/dockerd) seçilirse Docker CLI ile build edilen image’lar aynı Rancher Desktop daemon’ında görünür. Motor değişimi cluster’ı yeniden başlatabilir ve image cache’i ayırabilir.

macOS kurulumu (Apple Silicon dahil)

  1. Rancher Desktop resmi indirme sayfasından Mac için Apple Silicon (arm64) veya Intel (amd64) `.dmg` paketini indirin. Disk görüntüsünü açıp uygulamayı Applications’a taşıyın.
  2. Rancher Desktop’ı açın; ilk açılışta macOS güvenlik onayını verin. Preferences/Settings → Kubernetes sayfasında Kubernetes’i etkinleştirin, dağıtım olarak k3s’i ve mevcut stable Kubernetes sürümünü seçin; Apply/Restart’e basın.
  3. Preferences/Settings → Container Engine sayfasında containerd (önerilen) veya dockerd seçin. Eğitim boyunca değiştirmeyin; engine değişiminden sonra cluster yeniden başlayana kadar bekleyin.
  4. Resources/Virtual Machine ayarında CPU/RAM’i gözden geçirin: Kubernetes için en az 8 GB RAM ve 4 CPU önerilir. “Apply” sonrasında cluster durum göstergesi Running/Ready olmalı.
  5. Terminal’i yeniden açıp CLI’ları doğrulayın. Rancher Desktop kubectl’i PATH’e sunabilir; sürümden sürüme “Integrations”/“PATH management” tercihi değişebilir.
kubectl version --client
helm version --short
kubectl config current-context
kubectl get nodes -o wide

Bu depo ortamında görülenler: kubectl v1.37.1, Helm v4.2.3, current-context rancher-desktop. API şu oturumda kapalıydı; get nodes çalıştırılarak doğrulanmadı.

Windows kurulumu

  1. BIOS/UEFI virtualization, Windows “Virtual Machine Platform” ve WSL2’yi IT onayıyla etkinleştirin. Administrator PowerShell’de wsl --install (ilk kurulum) ve wsl --update çalıştırıp yeniden başlatın.
  2. Resmi Rancher Desktop indirme sayfasından Windows installer’ını indirin. Kurulum sırasında WSL2 altyapısını seçin/izin verin; kurulumdan sonra Rancher Desktop’ı başlatın.
  3. Rancher Desktop Preferences/Settings → Kubernetes → Kubernetes’i etkinleştir (k3s). Apply/Restart deyip cluster Ready olana kadar bekleyin.
  4. Preferences/Settings → Container Engine’de containerd (önerilen) veya dockerd seçin. Shell’in Docker/nerdctl CLI’si bu seçime uygun olmalı; aynı yerel image adının iki motorda otomatik paylaşılacağını varsaymayın.
  5. kubectl: Rancher Desktop’ın PATH entegrasyonunu etkinleştirin veya resmi Kubernetes CLI’ını kurun. Helm: `winget search Helm` ile kullanılabilir resmi paket kimliğini bulun, ardından `winget install --id Helm.Helm` (paket deposundaki kimliği arama sonucu ile teyit ederek) ya da resmi Helm release binary’sini PATH’e ekleyin.
  6. PowerShell’i kapatıp yeniden açın; aşağıdaki kontrolleri çalıştırın.
kubectl version --client
helm version --short
kubectl config current-context
kubectl get nodes -o wide
wsl --status

kubectl ve Helm yükleme / bağlam doğrulama

macOS’ta Homebrew varsa Helm kurulum ve kontrolü:

brew install helm
helm version --short
kubectl config get-contexts
kubectl config use-context rancher-desktop
kubectl config current-context

use-context yalnızca kubeconfig’de adı listelenen bağlamı seçer. Kurumsal ortamda bağlam adını önce get-contexts ile okuyun; mevcut kubeconfig’i gelişigüzel üzerine yazmayın.

Windows’ta Rancher Desktop kubectl entegrasyonu yoksa Kubernetes’in resmi Windows kubectl.exe binary’sini PATH’e ekleyin. Sürüm farkı ±1 minor aralığında tutulmalıdır; sunucu sürümünü cluster açılınca kubectl version ile ayrıca okuyun. Helm 4 kuruluysa chart API’si için helm create çıktısını bu sürümde kontrol edin.

Rancher Desktop k3s bileşenlerini doğrula

k3s kurulumlarında Traefik Ingress, metrics-server ve local-path provisioner çoğunlukla paketli/etkin varsayılanlardır; profilleme, sürüm ve cluster konfigürasyonu bunları kapatabilir. Bu nedenle “varsayılan vardır” yerine cluster’da gerçek objeleri sorgulayın. NetworkPolicy API objesinin kabul edilmesi policy enforcement’in çalıştığını tek başına kanıtlamaz; iki Pod’la izin/engelleme deneyi gerekir.

kubectl get pods -n kube-system
kubectl get deploy -n kube-system traefik metrics-server
kubectl get storageclass
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\\t"}{.status.nodeInfo.architecture}{"\\n"}{end}'
kubectl get --raw /apis/metrics.k8s.io/v1beta1/nodes

Beklenen yorum: Traefik ve metrics-server Deployment/Pod’ları Running; StorageClass’ta `local-path` gibi bir sınıf (Rancher Desktop’ta provisioner adı sürüme göre görülebilir); node architecture `arm64` veya `amd64`; metrics API’den node listesinin dönmesi. Gerçek cevap cluster başlatıldıktan sonra alınır.

NetworkPolicy’nin etkisini m05’te policy öncesi/sonrası gateway curl testiyle kanıtlayın. Pod etiketi ve namespace eşleşmesini kontrol edin; sadece YAML apply başarısı ağ eklentisini test etmez.

Alternatif ve sorun giderme başlangıcı

kind veya minikube de tek node laboratuvarı için uygundur. Minikube kullanıldığında `minikube image load logo/order-service:training` ile local image yüklenebilir; Rancher Desktop’a özgü Traefik/storage varsayımlarını ayrıca doğrulayın. Bu kısa alternatif, ana laboratuvar adımlarını değiştirmez.

  • Context başka cluster gösteriyorsa önce kubectl config current-context ve kubectl config get-contexts ile bakın.
  • API erişilemiyorsa Rancher Desktop Kubernetes status, engine durumunu ve cluster event/log ekranını kontrol edin; port-forward veya apply denemelerini API hazır olmadan sürdürmeyin.
  • Windows’ta path/quote hatasında PowerShell ile WSL shell’ini karıştırmayın; YAML ve komutları tek bir shell içinde çalıştırın.

Kurulum kontrol listesi

  • Rancher Desktop k3s Ready.
  • kubectl context rancher-desktop; node Ready ve architecture biliniyor.
  • Helm CLI kullanılabilir.
  • Container engine seçildi ve build edilen test image’ı cluster node tarafından görülebiliyor.
  • Traefik, metrics API, StorageClass ve NetworkPolicy davranışı kontrol edildi; eksikler not edildi.
