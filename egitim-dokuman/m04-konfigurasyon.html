m04 · Labels, ConfigMap, Secret ve kaynak politikaları

Konfigürasyonu image’dan ayırıp değişiklik etkisini sınırlayın; açık etiket ve seçim ilişkileriyle nesneleri yönetin.

1. Hedef ve çıktı

Gateway ve Order’ın config değerlerini ConfigMap/Secret kaynaklarına taşıyın; tutarlı app/part-of/version labels ve annotation kullanın; logo-ms ResourceQuota ve LimitRange uygulatıp çıktıyı sorgulayın.

2. Kurumsal katkı

Ortam değerlerini image içine gömmek farklı sürümleri çoğaltır, sır yönetimini ve dağıtım tekrarını zorlaştırır. ConfigMap ortam/ekip ayarlarını ayırır; Secret erişimini RBAC ile sınırlar; label’lar envanter, sahiplik ve release seçimini kolaylaştırır. Quota/LimitRange, bir iş yükünün kaynakları tüketerek diğerlerini etkilemesini ve kapasite tükenmesini sınırlar. Secret verisinin Base64 kodlanması şifreleme değildir; etcd şifrelemesi, en az ayrıcalıklı RBAC ve düzenli secret yenileme gerekir.

3. Kavram

Label makine tarafından seçilip filtrelenen anahtar-değer; annotation ise deploy/change metadata’sı, selector değildir. ConfigMap sır olmayan ayarları; Secret hassas ayar referansını taşır. ResourceQuota namespace toplam limitini; LimitRange tek container/Pod için varsayılan/min/max’i belirler. Benzetme: label dosya index’i, annotation dosyaya iliştirilmiş not; ConfigMap ortam ayar dosyası, Secret kilitli kasa anahtarı.

4. Proje senaryosu

K8s referansında `REDIS_PASSWORD=logo123`, H2 username/password ve DB URL düz metin env’dedir. Eğitim ConfigMap’te host/port/URL; Secret’ta eğitim parolalarını tutar. Image içine secret kopyalamayın. Config, secret, labels, quota ve limitrange dosyasını inceleyin.

`stringData` YAML’ında parola yine düz metin olarak repo’da görünür. Bu yalnızca sınıf örneğidir; üretim secret’ı Git’e koymayın.

5. Uygulama

  1. Başlangıçtaki Deployment env değerlerini kaydedin; label-selector ilişkisini çizerek inceleyin.
  2. `kubectl apply -f egitim-k8s/04-config/config.yaml` ile ConfigMap, Secret, ResourceQuota ve LimitRange’ı oluşturun. Secret içeriğini terminale veya kayda dökmeyin.
  3. Örnek olarak `kubectl set env deployment/order-service --from=configmap/order-config --from=secret/order-secret -n logo-ms` çalıştırın. Gateway, Inventory ve Payment için aynı komutu ilgili ConfigMap adıyla uygulayın; ardından Pod’ların hazır olduğunu doğrulayın. Inventory Logback’in Elasticsearch adresi kaynak kodda hâlâ `localhost:9200` olarak sabittir; yalnızca ConfigMap eklemek bu appender’ı düzeltmez, 01’deki öneri eğitmen onayı ve kod değişikliği gerektirir.
  4. Quota/LimitRange nesnelerinin `Used` ve `Hard` değerlerini okuyun; uygulanan label’ları `-L` ile listeleyin. Gerçek sınırı aşan kaynak talebini sınıfta denemeyin; üretim namespace’inde etkisini önceden değerlendirin.

6. YAML satırlarını anla

apiVersion: v1 core API’de ConfigMap/Secret; metadata.namespace hedef alan; data map string values. Secret type: Opaque, `stringData` plain inputs server-side base64’e çevirir. Deployment pod template içindeki `envFrom.configMapRef` anahtarları env yapar; seçili `secretKeyRef` parolayı en az kapsamda tüketir. `ResourceQuota.spec.hard` toplam sınır; `LimitRange.spec.limits` object-level min/max/default. `selector.matchLabels` Deployment selector immutable; labels must match template.

env:
  - name: REDIS_PASSWORD
    valueFrom:
      secretKeyRef:
        name: app-credentials
        key: redis-password
  - name: REDIS_HOST
    valueFrom:
      configMapKeyRef:
        name: app-config
        key: redis-host

7. macOS/Windows farkı

YAML path uses `/` on both OS. Komut satırında değer aktarırken shell’e özgü tırnak kullanımından kaçının; prefer manifest file. Üretilen Secret’ı yerelde sınarken zsh `printf` ile PowerShell `ConvertTo-SecureString` eşdeğer değildir; avoid placing real secrets in shell history. PowerShell çıktısı hassas nesne değerlerini gösterebilir; Yalnızca `kubectl get secret NAME -o name` ile Secret varlığını denetleyin.

8. Eğitmen notları

Say: “Secret objesi yetkisiz erişimi kendiliğinden engellemez; kim okuyabilir, nerede şifreli saklanır, nasıl döndürülür bunu ayrıca tanımlarız.” Show: redacted names vs secret payload. Duration: 45 min. Stop: “Base64 encryption mıdır?” No.

Common question: ConfigMap update env var in an existing Pod does not mutate process environment; roll out a Pod restart. Labels are selection semantics; annotation doesn't select resources. Don't dump actual values to projector.

9. Katılımcı alıştırması

Change only Order’s Redis host in ConfigMap to a deliberate invalid DNS name, observe startup/error, restore `redis`, and verify ready. Hint: env values read at container start; configuration reference key spelling must match.

Verify with `kubectl describe pod ...` (inspect env source name, not actual credentials), `kubectl logs` and `kubectl get pods -L app`.

Show solution

Update app-config `redis-host: redis`, apply it, then `kubectl rollout restart deployment/order-service -n logo-ms`; watch rollout and check Order logs. Re-read secret by name only. The exercise demonstrates DNS config and process environment startup semantics, not secret encryption.

10. Hata ve çözümleri

  • CreateContainerConfigError: Secret/ConfigMap missing or key typo; `describe pod` events.
  • Quota exceeded: inspect `describe quota`, requested vs hard; don't delete limits blindly.
  • Config changed but app old: restart/reload semantics; envFrom values apply on Pod creation.
  • Selector changed: immutable selector; choose stable labels and manage controlled Deployment replacement.

11. Üretimde fark

Üretimde dış secret store/operator veya şifreli secret akışı, at-rest encryption, RBAC, rotation, kısa ömürlü credential ve audit kullanılır. Quota/limit ölçülmüş SLO ve workload profiline göre boyutlandırılır. Standart label’lar kullanın; hassas veriyi label/annotation’a yazmayın.

12. Modül özeti ve kontrol listesi

  • Label and annotation roles are clear.
  • ConfigMap and Secret are referenced by actual Pod templates.
  • No real credential was placed in repository/terminal.
  • Quota and LimitRange show expected namespace/resource constraints.
