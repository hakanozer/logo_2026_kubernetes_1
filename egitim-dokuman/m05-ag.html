IP’yi DNS’e çevir

m05 · Servis keşfi, Service türleri ve NetworkPolicy

Gateway’den DNS ile backend’lere erişin; dış trafik türlerini ayırt edin ve erişimi en az gereken seviyeye indirin.

1. Hedef ve çıktı

Gateway → `order-service.logo-ms.svc.cluster.local` DNS akışını test edin; ClusterIP/NodePort/LoadBalancer/ExternalName örneklerini karşılaştırın. NetworkPolicy ile yalnızca gateway Pod’larının dört HTTP servis Pod’una inbound erişebildiğini uygulayın.

2. Kurumsal katkı

Pod IP’si değişebilir; uygulama koduna Pod IP’si yazmak yeni dağıtımda arızaya yol açar. Service DNS’i kararlı uygulama adresi ve servis keşfi sağlar. NetworkPolicy, servisler arası gereksiz erişimi ve yanal hareketi sınırlandırarak olayın etki alanını ve uyumluluk riskini küçültür. Gereksiz NodePort açmak saldırı yüzeyini büyütür. Policy’nin gerçekten uygulandığını kullanılan CNI ile test edin; manifestin kabul edilmesi tek başına enforcement kanıtı değildir.

3. Kavram

Service selector endpoint’leri seçer. ClusterIP cluster içi; NodePort node IP:port; LoadBalancer cloud/external entry; ExternalName DNS CNAME alias’ıdır, Pod selector/proxy değildir. DNS `service.namespace.svc.cluster.local` kullanır. NetworkPolicy, Pod selector’larına göre L3/L4 seviyesinde izin/ret kuralı tanımlar; yalnızca CNI eklentisi destekliyorsa uygulanır. Benzetme: Service şirket santrali, DNS ise yayımlanmış dahili numara gibidir; policy is an access badge.

4. Proje senaryosu

Gateway env’leri referans YAML’da internal service DNS kullanır. Order additionally accesses Redis/Kafka; Inventory Elasticsearch; Payment Kafka. `network.Bu YAML, uygulamanın HTTP Pod’larına gelen erişimi kısıtlar; gerekli altyapıya giden çıkışı engellemez. Alıştırmada tüm trafiği varsayılan olarak reddeden bir policy uygulanmaz. Service and policy examples.

5. Uygulama adımları

  1. Gateway Pod içinden curl/wget backend DNS’ine gönderin; `port-forward` gerekmez.
  2. Service endpoints selector’larının Pod label’larını seçtiğini doğrulayın.
  3. Service type examples and ExternalName are applied in isolation; don't expose development backends to the public network.
  4. Policy apply before/after test from gateway and a separate debug Pod. If NetworkPolicy unsupported, record failure not success.
  5. DNS troubleshooting: CoreDNS Pod and service name/port inspect.

6. YAML açıklaması

Service `spec.type` erişim modelini seçer; selector, Pod template label’larıyla birebir eşleşmelidir. Port tanımında Service `port` ve Pod `targetPort` yer alır. ExternalName için `spec.externalName` DNS alias’ı tanımlar; selector/proxy değildir. NetworkPolicy `podSelector` hedef Pod’ları seçer, `policyTypes: [Ingress]` inbound kuralı belirtir; `from` kaynak namespace/Pod’larını, `ports` L4 portlarını tanımlar. Aynı peer öğesindeki namespaceSelector ve podSelector birlikte AND koşuludur.

7. macOS / Windows

Kubernetes commands same across host shells. `kubectl exec ... -- sh -c` command quoting differs: PowerShell single-quoted arguments pass inner command as string; zsh also single-quote. Use test/debug image with known shell tools; avoid PowerShell interpolation inside manifest snippets.

8. Eğitmen notları

Say: “Clients depend on a stable Service name, not a Pod IP.” Show: EndpointSlice changes after Pod replacement, DNS success, policy denial. Duration: 45 min. Stop: “ExternalName traffic gets proxied by Kubernetes?” No, it resolves to an external DNS name.

Sık soru: ClusterIP’yi port-forward ile yerel makineden test etmek onu public yapar mı? Hayır. Uygulama image’ında curl yoksa bu normaldir; geçici, onaylı debug Pod kullanın. NetworkPolicy için enforcement desteği gerekir; bu oturumda cluster API erişimi olmadığından davranış doğrulanamadı.

9. Katılımcı alıştırması

From Gateway resolve Order; from an unlabelled debug Pod attempt HTTP. Apply policy; confirm Gateway still works and debug Pod is blocked. Confirm external alias resolves only when its external target is resolvable.

Verification: `kubectl get svc,endpointslice,networkpolicy -n logo-ms`; test both request origins.

Show solution

Check Service port 8081 → targetPort 8081 and endpoint addresses. DNS short name works in same namespace. Policy selects application destination labels and permits source Pod label `app=api-gateway` in `logo-ms`; source debug Pod fails. If both succeed, policy enforcement/CNI/labels need investigation; don't claim security is active.

10. Sık hatalar ve çözümleri

  • No endpoints: selector/labels mismatch or Pods not ready.
  • DNS resolves but request times out: Service targetPort, process listening address or NetworkPolicy.
  • NetworkPolicy apply ok but no traffic change: enforcement unsupported/disabled; verify CNI behavior.
  • Wrong type: ExternalName is DNS alias, not in-cluster forwarding.

11. Üretimde fark

HTTP dış trafiği için Ingress/Gateway API veya yönetilen LoadBalancer kullanın; gelişigüzel NodePort çoğaltmayın. NetworkPolicy tasarımı DNS egress, telemetry, broker, veri depoları ve dış servisleri de hesaba katmalıdır. K8s NetworkPolicy L3/L4 kuralıdır; HTTP path authorization sağlamaz.

12. Modül özeti ve kontrol listesi

  • Service is stable virtual endpoint; Pod endpoint IP can change.
  • Port vs targetPort understood.
  • All four Service types and ExternalName compared.
  • Policy enforcement was actually tested, not inferred from apply success.
