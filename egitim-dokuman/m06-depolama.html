Pod ömründen uzun veri

m06 · Volume, PV, PVC ve StorageClass

Order H2 verisini `emptyDir` ile kaybettirip yerel PVC ile koruyun; broker ve Elasticsearch volume claim’lerini tanıyın.

1. Hedef ve çıktı

Order Pod’unu silip `emptyDir` verisinin kaybolduğunu deneyimleyin; PVC ile Pod recreation sonrasında aynı dosya verisinin kaldığını doğrulayın. Kafka/Elasticsearch stateful claim’lerini görün. Çıktı: bound PVC, mounted volume ve kalıcılık sınırını açıklayabilen katılımcı.

2. Kurumsal katkı

Pod ephemeral’dır; local filesystem’e yazılmış kayıt node/process lifecycle’ına bağlı kalır. PV/PVC app lifecycle ile storage lifecycle’ını ayırır ve pod değişiminde veriyi tekrar bağlar. StorageClass provisioner/performance/policy seçimidir. Bu, recovery time ve data loss riskini azaltabilir; PVC tek başına backup, replication, consistency, disaster recovery veya node failure protection değildir.

3. Kavram

Volume Pod’a mount edilir; PV cluster storage kaynağı; PVC namespace içi storage isteği; StorageClass dynamic provisioning policy. `emptyDir` Pod yaşadığı sürece durur ve Pod yeniden yaratılınca silinir. PVC claim olarak kalır; volume binding reclaim policy’ye göre korunabilir veya silinebilir. Benzetme: Pod kiralık çalışma masası; PVC arşiv dolabı; StorageClass dolabın tipi ve kim tarafından sağlandığı.

4. Proje senaryosu

Referans Order Deployment `/data` için `emptyDir`; datasource file URL `/data/order-service...`. Redis/Kafka/Zookeeper/Elasticsearch K8s referansında kalıcı mount kullanmıyor. `egitim-k8s/06-storage/` PVC/StatefulSet örneklerini içerir. Yerel `local-path` diski yalnızca tek node’un host diskidir; node kaybı yedekleme değildir.

5. Uygulama adımları

  1. Order’da test kaydı oluşturup API’den doğrulayın; Deployment’ın yönettiği Pod’u silin ve `emptyDir` nedeniyle verinin kaybolduğunu gözlemleyin.
  2. `kubectl apply -f egitim-k8s/06-storage/order-pvc.yaml` ile PVC’yi oluşturun. `WaitForFirstConsumer` kullanan StorageClass’ta Pod claim’i tüketene kadar PVC’nin `Pending` kalması normaldir.
  3. `kubectl apply -f egitim-k8s/06-storage/order-persistent.yaml` ile Order Deployment’ını aynı claim’i `/data` konumuna bağlayacak şekilde güncelleyin; Pod hazır olduktan sonra yeni kayıt yazın, Pod’u silip kayıtların kaldığını doğrulayın.
  4. Altyapı StatefulSet’lerinde `emptyDir` yerine `volumeClaimTemplates` kullanmak için kontrollü kesinti gerekir. Önce `kubectl scale --replicas=0 statefulset/redis statefulset/zookeeper statefulset/kafka statefulset/elasticsearch -n logo-ms` ile Pod’ları durdurun; sonra `kubectl delete statefulset redis zookeeper kafka elasticsearch -n logo-ms` ile StatefulSet nesnelerini silin. Mevcut Service’ler kalır. `kubectl apply -f egitim-k8s/06-storage/infrastructure-persistent.yaml` ile PVC şablonlu StatefulSet’leri yeniden oluşturup Pod’ların Ready olmasını bekleyin. Bu yeniden oluşturma laboratuvar verisini kaybettirebilir; gerçek ortamda yedekleme/taşıma planı olmadan yapmayın.
  5. StorageClass provisioner, binding mode ve reclaim policy değerlerini inceleyin; test sonunda PVC’leri silmeyin. PV silme/geri kazanım davranışı storage provider’a göre değişir.

6. YAML açıklaması

PVC is `apiVersion: v1`, `kind: PersistentVolumeClaim`; `accessModes` describes attach semantics (e.g. ReadWriteOnce), `resources.requests.storage` capacity, `storageClassName` provisioner. Pod `volumes[].persistentVolumeClaim.claimName` references exact PVC; `volumeMounts.mountPath` is path in container. Container içindeki dosya yolu ile datasource URL aynı mount noktasını kullanmalıdır. StatefulSet `volumeClaimTemplates` creates per-ordinal claims; Aynı ReadWriteOnce claim’i paylaşan sıradan Deployment replikaları genellikle birden çok node’a bağlanamaz ve bağımsız veritabanı örnekleri oluşturmaz.

7. macOS / Windows farkı

Manifest syntax and kubectl same. local-path dosyaları doğrudan host dosya sisteminde değil, Rancher Desktop sanal makinesi içinde bulunabilir. Don't edit the VM's internal path manually. Path `jdbc:h2:file:/data/order-service` is Linux container path on both host OSes.

8. Eğitmen notları

Say: “Persistent claim, Pod’dan uzun yaşar; ama felaket kurtarma planı değildir.” Show: PVC Pending→Bound event and DB list before/after Pod replacement. Duration: 50 min. Stop: “PVC bound ise backup tamam mı?” No.

Do not delete PVC/namespace before recording evidence. Local-path may use delayed binding. Replacing a deployment may briefly create two pods competing to mount a single claim; check rollout strategy and RWO constraints. For demo use one replica.

9. Katılımcı alıştırması

Create one test record, delete only Order Pod, show loss with emptyDir; reapply PVC-backed template, create another record, delete Pod again, and confirm data remains. Hint: verify which path Spring H2 actually uses.

Verification: Order list endpoint before and after; `kubectl get pod,pvc -n logo-ms`.

Show solution

Referans Deployment `SPRING_DATASOURCE_URL=jdbc:h2:file:/data/order-service...` değerini ve `/data` üzerindeki `emptyDir` mount’unu kullanır. Pod silinince emptyDir kaybolur. PVC aynı mount noktasında kalırsa controller’ın oluşturduğu yeni Pod veriyi yeniden görür. Sonuç farklıysa H2 write/commit durumunu, mount edilen claim’i ve URL/path eşleşmesini doğrulayın; yalnızca Pod status’tan veri kalıcılığı çıkarmayın.

10. Sık hatalar ve çözümleri

  • PVC Pending: inspect events, class/provisioner, requested access mode/capacity and pod scheduling.
  • Mount error: claim name/path mismatch or access mode/zone conflict.
  • No data after new Pod: file URL differs, claim wasn't mounted, or PVC was deleted/recreated.
  • Permission denied: container UID/fsGroup and volume ownership; coordinate non-root hardening.

11. Üretimde fark

Üretimde çoğaltılmış storage/zone topology, CSI snapshot, backup retention, şifreleme, restore provası, RPO/RTO, reclaim policy ve veritabanına özgü yedekleme değerlendirilir. PVC’ye yeniden bağlanmak Redis/Kafka/Elasticsearch state’ini tutarlı veya yüksek erişilebilir yapmaz. H2 eğitim DB’sidir; replikalı üretim DB’si değildir.

12. Modül özeti ve kontrol listesi

  • emptyDir Pod lifetime and data loss demonstrated.
  • PVC Bound, mounted at exact H2 path, reused after Pod recreation.
  • StatefulSet PVC claim template understood.
  • Local-path vs backup/DR limitation stated.
