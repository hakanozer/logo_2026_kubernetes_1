Manifestleri paketle

m12 · Helm chart, values ve release yaşam döngüsü

Beş mikroservisi ortak chart olarak paketleyin; dev/prod values’larını ayırın ve release upgrade/rollback süreçlerini uygulayın.

1. Hedef ve çıktı

logo-ms Helm chart ile beş Deployment/Service ve ortak config/secret kaynaklarını render edin. `values-dev.yaml` ve `values-prod.yaml` ile replica/image farkını gösterin; local dev release install/upgrade/history/rollback yapın.

2. Kurumsal katkı

Chart, tekrar kullanılabilir release tanımlarını standartlaştırır; copy/paste farklılığını azaltır ve ortam değerlerini görünür kılar. Revision history ve rollback kontrollü değişikliği kolaylaştırır. Ancak Helm tek başına iş uyumluluğunu doğrulamaz, Secret yaşam döngüsünü çözmez veya render edilmiş YAML incelemesini gereksiz kılmaz. Ortam değerlerini açıkça ayırmak ekip hızını artırır; prod Secret’larını values dosyasında saklamak sızıntı riskini büyütür.

3. Kavram

Chart, template’ler + Chart.yaml + varsayılan values dosyalarından oluşur; release, bu chart’ın namespace’te kurulu örneğidir; values render sırasında template değerlerini değiştirir. `helm template` yerel render yapar; `helm upgrade --install` release yaratır veya günceller; rollback önceki revision’a döner. Benzetme: chart tekrar kullanılabilir tarif, values ortam malzemeleri, release o tarifin belirli ortamdaki kurulumu.

4. Proje senaryosu

Mevcut uygulama Deployment’larında selector, image, port ve env tanımları tekrarlanır. Eğitim chart’ı beş API workload’unu image tag’i ve replica sayısı değiştirilebilir şekilde paketler. Stateful altyapı m03/m06 manifestlerinde ayrı yaşam döngüsüne sahiptir; chart notu bağımlılıkları açıklar. Üretimde database/Kafka chart/operator sahipliğini ayırın ve Secret’ı dış secret store ile yönetin.

5. Adım adım uygulama

  1. Kurulumdan önce `Chart.yaml`, varsayılan `values.yaml`, helper şablonları ve resource template’lerini inceleyin. Chart’ı lint edin; dev/prod values ile render edip namespace, image etiketleri, Secret referansları ve portları kontrol edin.
  2. Chart Order için `order-data` PVC’sini kullanır; önce m06 adımında PVC’nin oluşturulduğunu ve Pod tarafından bağlandığını doğrulayın. Altyapı StatefulSet’lerini de ayrı uygulayın; bu chart Redis/Kafka/Elasticsearch kurmaz.
  3. Dev release’i `logo-ms` namespace’ine yükleyin. Secret olmayan güvenli bir değeri değiştirip upgrade yapın; status/history ve Deployment template’ini inceleyin, sonra önceki revision’a rollback edin.

6. Chart/YAML açıklaması

Chart.yaml chart metadata/name/version/appVersion; `values.yaml` defaults; `templates/` Kubernetes manifests with Go template expressions; `_helpers.tpl` shared names/labels; `.helmignore` package exclusions. Doğru YAML türlerini kullanın (`replicaCount: 2`, string image tag’i) ve env değerlerini tırnaklayın. Values dosyalarının sırası önemlidir: sonraki `-f` önceki dosyadaki aynı anahtarı ezer; don't store real secrets. Üretilen selector release’ler arasında sabit kalmalıdır.

Kurulumda Helm template’leri render edip Kubernetes kaynaklarını API’ye gönderir. Release history chart/config metadata’sını saklar; hassas render edilmiş değerler release Secret’larında bulunabileceğinden Helm storage RBAC’ı önemlidir.

7. macOS / Windows

Helm CLI same; quote paths with spaces. Repository içindeki göreli yolu ve `/` ayırıcılarını tercih edin. PowerShell `--set` values with commas, braces and dots can be parsed differently; use `-f values-dev.yaml`. Run `helm version --short` and retain output because v3/v4 command/plugin/chart compatibility differs.

8. Eğitmen notları

Say: “Helm templates Kubernetes objects; Kubernetes still reconciles them.” Show: `helm template` diff vs `helm list/history`. Duration: 50 min. Stop: “A release rollback undoes H2 schema migration?” No.

Eğitim chart’ı uygulama workload’larını yönetir; altyapı bağımlılıkları stateful laboratuvarlarda ayrıca apply edilir. `values-prod.yaml` yalnızca gösterim içindir: gerçek prod kullanımı öncesi erişilebilir registry’de sabit digest, dış Secret, HA replika/depolama/ağ/güvenlik incelemesi gerekir.

9. Katılımcı alıştırması

Install `logo-dev` with dev values, scale one service via values, upgrade, inspect revision, rollback. Render prod values without applying to local single-node. Compare image tags, replicas and environment strategy.

Verify `helm template`, `helm status`, `helm history`, `kubectl get deploy -n logo-ms`.

Show solution

Lint and render first. Use `helm upgrade --install` with dev file, then adjust a non-secret replica value and upgrade. `helm history` shows new revision. `helm rollback` creates a new revision using selected prior chart/config. Prod values render to YAML but are not applied to a one-node training cluster.

10. Sık hatalar ve çözümleri

  • Template parse error: lint first and inspect line/indentation/type.
  • Release has no ready pods: read deployment/pod events, dependencies and images; Helm success alone isn't app-level health.
  • Wrong environment values: print render and review `helm get values` safely; avoid secrets output.
  • Rollback assumes DB recovery: use database backup/migration strategy separately.

11. Üretimde fark

Version chart as artifact, sign/provenance, use immutable images/digests, schemas, policy tests and promotion rather than ad hoc prod `--set`. Separate app and infra ownership and secret integrations. Rollback compatibility depends on API/storage schema. GitOps controller usually becomes release reconciler; avoid two independent writers fighting live state.

12. Modül özeti ve kontrol listesi

  • Chart layout and values override understood.
  • Lint/render before install.
  • Install/upgrade/history/rollback observed.
  • Infra lifecycle, secrets and DB rollback limits explicit.
