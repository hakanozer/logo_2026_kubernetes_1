m13 · Pod hata analizi ve kubectl debug

ImagePullBackOff, CrashLoopBackOff, yanlış Service selector/port ve network problemlerini ortak teşhis sırasıyla çözün.

1. Hedef ve çıktı

Üç kontrollü arızayı üretin, her biri için state → event → container log → selector/network kanıt zinciri kurun ve düzeltmeyi doğrulayın. Çıktı: her arızanın nedeni/çözümünü içeren runbook; cluster root cause assumptions değil evidence.

2. Kurumsal katkı

Yapılandırılmış teşhis, ortalama onarım süresini (MTTR) kısaltır ve kanıtsız hotfix’leri önler. Belirtiler; control plane zamanlaması, registry erişimi, uygulama süreci ve Service yönlendirmesi arasındaki farkı gösterir. Önceki container log’larını, event’leri ve zaman damgalarını saklamak olay devri, denetim ve güvenli rollback’i destekler. Üretimde tekrar tekrar deneme yeni kesintiler yaratabilir; önce salt-okunur teşhis yapmak değişiklik riskini sınırlar.

3. Kavram

Pod phase’i ile container state’i farklıdır. `Pending` scheduler/PVC/kaynak sorununa; `ImagePullBackOff` image adı/registry/credential hatasına; `CrashLoopBackOff` process’in tekrar tekrar çıkmasına işaret edebilir. `Running`, Pod’un Ready veya erişilebilir olduğunu garanti etmez. Service endpoint seçer; çalışan Pod bile yanlış Service selector/port’u telafi etmez. Ephemeral debug container Pod’a tanılama aracı ekler; yalnızca onaylı image kullanın.

Teşhis sırası: context/namespace → `get` ile durum → `describe` event’leri → mevcut ve `--previous` loglar → owner Deployment/ReplicaSet/config → endpoint/DNS/network → tek ve geri alınabilir düzeltme → rollout/health doğrulaması.

4. Proje senaryosu

Laboratuvarda `bad-image` (`ImagePullBackOff`), süreç hatası veren `bad-env` (`CrashLoopBackOff`) ve boş/başarısız endpoint oluşturan `wrong-selector` veya `wrong-port` Service senaryoları bulunur. Bilerek bozulan manifestler ayrıdır; üretime uygulanmamalı ve normal kurulumda kullanılmamalıdır.

5. Adım adım uygulama diagnosis

  1. `logo-ms` Pod’larını `-o wide` ile listeleyin; STATUS, READY, restart sayısı ve NODE alanlarını kaydedin.
  2. İlgili Pod ve Deployment üzerinde kubectl describe çalıştırın; Events bölümünü zaman sırasına göre okuyun.
  3. Güncel container loglarını alın; yeniden başladıysa --previous kullanın. Secret değerlerini yazdırmadan image/env kaynaklarını adları üzerinden inceleyin.
  4. Service arızasında selector, EndpointSlice, targetPort ve container’ın dinlediği portu karşılaştırın. Geçici debug Pod’undan DNS ve bağlantıyı sınayın.
  5. Yalnızca hata nedenini kanıtladıktan sonra tek bir düzeltme yapın; rollout’u izleyip HTTP/event akışını doğrulayın. Sonunda yalnızca eğitim için oluşturulan bozuk workload’ları silin.

6. Hatalı YAML açıklaması

Bad image case changes only `spec.template.spec.containers[].image`; pull policy/event differentiates registry lookup from app runtime. Bad environment case references intentionally missing required value/invalid host; an existing app may not exit immediately, so use a documented bad command or impossible config setting to ensure clear failure; manifest itself identifies intentional nature. Wrong selector uses Service `spec.selector.app` that does not match Pod labels; EndpointSlice empty. Wrong port sets Service `targetPort` to unused port; endpoints can exist but connections fail. Restore working manifest after each demonstration.

7. macOS / Windows

`kubectl` command flags same. Shell syntax for remote command after `--` may need quoting differences; use one-line simple commands. `curl.exe` for Windows; BusyBox `wget` for an in-cluster test. Debug image may be unavailable on internet-restricted network; preload/mirror it before training.

8. Eğitmen notları

Say: “Status is a symptom; Events and logs are evidence.” Show: three failures with separate first command: describe for pull, previous logs for crash, EndpointSlice for routing. Duration: 55 min. Stop: “We have a running Pod; is the Service necessarily reachable?” No.

Apply bad manifests one at a time, only in training namespace. Keep a known-good baseline. Avoid `kubectl delete all --all`, never print secret env values, and after each fix verify user path through Gateway. If time short, skip debug ephemeral container and do logs/events/EndpointSlice.

9. Katılımcı alıştırması

Draw the symptom→evidence→root cause→fix chain for each failure. Do not use logs as the only diagnostic for Service selector failure. Hint: Event object for image; previous logs for process exit; EndpointSlice for Service target membership.

Verification: broken Pod gone/fixed; Deployment available; real Gateway endpoint responds. Collect `describe`, `logs --previous`, and `get endpointslice` output.

Show solution

ImagePullBackOff: check exact image name/tag, registry reachability and pull secret (training images use local `Never`, so local cache is required). CrashLoopBackOff: read `--previous`, correct env/config and restart rollout. Wrong selector: align Service selector to template labels. Wrong port: match Service targetPort to process listen port (8081 for Order). Then `rollout status` and HTTP call.

10. Sık teşhis hataları

  • Readiness 0 treated as process crash; inspect container state/restart count.
  • Pod IP curl works but Service fails; inspect selector/port/endpoints/network policy.
  • `kubectl logs` shows only new container; include `--previous` after restart.
  • Debug sidecar blocked by image access/RBAC/PSS; use events and prepared toolbox image.

11. Üretimde fark

Üretimde incident komuta düzeni, change freeze/onay, telemetry korelasyonu, salt-okunur erişim, onaylı debug image ve değiştirilemez olay kaydı kullanılır. Müdahale müşteri etkisini, zaman çizelgesini, mitigation/rollback’i ve takip işini kapsar. Credential paylaşmayın veya regüle cluster’da rastgele debug image çalıştırmayın. Root cause tekrarlanabilir, kalıcı düzeltme de testle korunabilir olmalıdır.

12. Modül özeti ve kontrol listesi

  • First diagnostic sequence memorized.
  • Image pull vs app crash differentiated by events and logs.
  • Selector/port path verified by EndpointSlice and test request.
  • Broken workload removed and baseline restored.
